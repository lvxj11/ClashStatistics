# 多数据源在线状态

在线状态页（时间热度图）自 v2.0.0 起支持多个数据源。默认视图仍是 Clash 代理，用户可在页面顶部的「数据源」下拉里切换；只有一条数据源时直接显示其名称，不占一个单选项的下拉。数据源定义在 `/data-sources` 管理页维护，改动即时生效、无需重启。

## 统计与热度分离

- 目标统计、客户端统计**只**来自 Clash 的 `connections`，行为不变。
- 在线状态热度：Clash 从 `connections` 现算，新数据源写入独立的 `activity` 表，两者共用 `GetGanttData(source, date)` 出口并统一返回 `[]GanttRow`。
- 路由器数据**不混入**代理统计，`activity` 与 `connections` 是两张独立的表，各自随保留天数清理。

## 活跃强度（1–6 档）

- 颜色表示「相对本源有多忙」，各源把原始活跃量按阈值映射到 1–6 档，便于跨源对比，而不是一个跨源可比的绝对数字。
- 档位之外，接口同时返回每槽原始活跃量（`RawValues`）：在线状态页悬停色块与峰值文案会显示绝对数值，并按源标注单位（Clash → 并发连接数，推送源 → 上行流数）。颜色仍按档位取色，不受原始数值量级影响。
- **只统计连接数 / 上行流数**：字节、包量加权代价大、收益不明显，且会破坏跨源归一化、重新引入下行 / NAT 归属问题，因此不采用；原 Clash 数据的字节字段是逐连接累计值、缺少按槽时间序列，要加权得新建聚合表，得不偿失。
- **阈值可按数据源自定义**：阈值是 5 个分界值（逗号分隔，如 `2,20,50,150,254`），超过最后一个即 6 档；只是视觉参数，不受传输字节限制（槽值落库为 `uint16`、上限 65535，改造前 `[288]byte` / 封顶 255 的单字节约束已不存在）。
- 全局默认 `2 / 20 / 50 / 150 / 254`（与改造前前端一致，单 Clash 源逐槽颜色零回归）。在 `/data-sources` 页编辑数据源时开启「自定义热度阈值」即可单独设置，关闭 / 留空则用默认；必须是 5 个严格递增的正整数，`PUT` 时校验。每台设备、每个用户的量级不同，阈值不写死在代码里。
- IPFIX 源用上行流数，被 `active-flow-timeout=1m` 长流切片放大，量级远高于代理连接数（真机中位 30 vs 1、p90 437 vs 7），套默认阈值容易「一片红」，一般要单独调高。**若把 RouterOS 的 `active-flow-timeout` 调大（如 5m），原始值会整体回落到连接数量级，自定义阈值也要同步下调。**
- 热度槽宽仍是 5 分钟；`active-flow-timeout=1m` 是长流导出超时，不是采集频率。

## 数据源定义与管理页

- 数据源定义存于 `data_sources` 表，在 `/data-sources` 页增删改、启停、设默认；`PUT` / `DELETE` 后即时重建采集器。
- 每行还带 `thresholds` / `custom_thresholds`（自定义热度阈值，见上「活跃强度」）；改动只影响该源的在线状态颜色，立即生效、无需重启。
- 系统级配置（Web 端口、日志、保留天数）仍在 `config.toml` / 环境变量，不进表。
- **凭据只存引用**（环境变量名，如 `CLASH_SECRET`），不存明文；管理页与接口只回显「是否已配置」，不回显值。
- 内置 `clash` 源不能删除，只能停用，避免升级后失去默认视图。

### Clash 源（代理轮询）

轮询外部控制器 `/connections`，行为与改造前一致；地址、轮询间隔、凭据引用可在管理页配置。凭据真值从凭据引用指向的环境变量读取，取不到时回落到 `config.toml` 的 `[clash].secret`。

### IPFIX 源（路由器流量推送）

- 接收路由器 UDP 推送的 NetFlow v9 / IPFIX 报文，只写 `activity` 表，**落库即聚合、不存原始流**：一条上行流在其存活区间覆盖的每个 5 分钟槽各累加一次。
- IPv4 模板字段（IANA IPFIX IE）：`4, 7, 8, 11, 12, 21, 22, 60`，共 8 字段 / 22 字节；一期忽略 IPv6 模板。
- **只算上行**：仅当源地址（IE8 `sourceIPv4Address`）落在 LAN 网段才归属给客户端。IPFIX 是单向流，配合上行过滤可避免同一连接上下行重复计数，因此不需要 NAT / MAC 字段来反查下行归属。
- `first/last-forwarded`（IE22 / IE21）是相对设备启动的毫秒值，用报文头的绝对 Export Time 反推 bootTime（取近期样本中位数抗抖动）再换算成绝对时间区间。
- 排除 `exclude_ips`（通常填网关）与路由器（导出源）自身 IP。
- **无感认证**：RouterOS Traffic Flow 走 UDP 推送到采集机 IP:端口，零账号密码；官方 REST API 必须 Basic Auth，不用它。

#### RouterOS Traffic Flow 配置要点

- Traffic Flow 目标指向运行本程序的主机 IP 与 UDP 端口（默认 `2055`）。
- 模板只保留上面 8 个 IPv4 字段，取消 NAT Src./Dst. Address 与 Src./Dst. MAC Address。
- 网络 / 防火墙需放行到采集机该 UDP 端口的报文；Docker 部署要发布 UDP 端口（见下）。

## 配置项（bootstrap 默认值）

数据源运行时的真实配置在 `data_sources` 表；下面的 `config.toml` / 环境变量只用于**首次启动（表为空）时写入内置 IPFIX 源**，以及兼容纯环境变量部署。详见 [配置与部署](configuration.md)。

| 配置项 | 环境变量 | 默认值 | 说明 |
|---|---|---|---|
| `[ipfix].port` | `IPFIX_PORT` | `2055` | UDP 监听端口 |
| `[ipfix].lan` | `IPFIX_LAN` | 本机 IPv4 自动推断 /24 | LAN 网段（逗号分隔），决定哪些源地址算客户端 |
| `[ipfix].exclude_ips` | `IPFIX_EXCLUDE_IPS` | 空 | 排除 IP（逗号分隔），通常填网关 |

Docker 接收推送需发布 UDP 端口，例如 `-p 2055:2055/udp`，compose 里写 `"2055:2055/udp"`。若容器用 macvlan 拿到局域网同网段 IP，推送可直接到容器 IP，按需决定是否发布端口。

## 版本与迁移基线

- v2.0.0 是较大的一次改动：多数据源、`Collector` 采集层抽象、活跃强度归一化、数据源管理页。
- **数据库迁移基线为 v1.0.4**：升级新增 `activity`、`data_sources` 两张表（`CREATE TABLE IF NOT EXISTS`），`connections` 与 `client_names` 结构不变。
- 之后加入的自定义阈值列通过幂等 `ALTER TABLE` 补齐（`PRAGMA table_info` 判列）；仅从旧版升级那一次把内置 `ipfix` 源的阈值迁为 `2,50,200,600,900` 并开启自定义，保证升级零回退，此后管理页改动不会被覆盖。
- **v1.0.3 及更早版本的历史迁移 / 兼容代码已移除**（旧索引清理、`inbound_name` 名称清理等）。从这些版本升级请先用 v1.0.4 过渡，再升到 v2.0.0。
