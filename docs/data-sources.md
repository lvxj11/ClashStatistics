# 多数据源在线状态

在线状态页（时间热度图）自 v2.0.0 起支持多个数据源，**v3.0.0 起统一在数据源配置页切换**：页面上不再各自放数据源下拉（避免统计页各自切换导致数据不配套产生误会），而是跟随数据源页的「在线默认」单选源，页顶静态显示当前跟随的源名并给出跳转链接。数据源定义在 `/data-sources` 管理页维护，改动即时生效、无需重启。

## 按源隔离落盘（v3.0.0）

所有数据源都按不同来源隔离落盘，方便分别统计：

- `connections`（Clash 连接）改为 **`(source, id)` 复合主键**，每个 Clash 源写入时打上自己的数据源 ID；在线状态与目标 / 客户端统计都从这一张表按 `source` 过滤。
- `flow_slots`（IPFIX / NetFlow v9 去重行）主键本来就含 `source`，按源隔离。
- 两者共用 `GetGanttData(source, date)` 出口：按真实数据源类型路由（clash → `connections WHERE source=该ID`、ipfix → `flow_slots WHERE source=该ID`），统一返回 `[]GanttRow`，不再有硬编码 `clash` 或混合口径。

## 三个独立开关

数据源页的三个开关各管一件事、互不影响，目标 / 客户端统计统一在本页配置，不在统计页分别切换：

| 开关 | 字段 | 作用 |
|---|---|---|
| **采集** | `enabled` | 只控制是否起采集器、是否写库（落盘开关）；与能否被选中无关，关闭采集的源仍可被设为在线默认、查看历史数据 |
| **汇总** | `in_summary` | 只控制该 Clash 源是否进入目标 / 客户端统计（含明细弹窗）；IPFIX 源不写 `connections`、恒为 0，不参与这两页。默认 1（开启） |
| **在线默认** | `is_default` | 单选，只决定在线状态页跟随哪个源；设默认时后端清掉其它源的默认标记。未显式设置时回落第一个启用「采集」的源 |

## 统计与热度分离

- 目标统计、客户端统计**只**来自 Clash 的 `connections`，且只汇总「采集遗留的无来源数据（`source=''`）」+「汇总开关开启的 Clash 源」；明细弹窗用同一套过滤条件，保证口径一致。IPFIX 源不参与这两页。
- 在线状态热度：严格按「在线默认」源隔离取数 —— Clash 从 `connections`（`WHERE source=该源ID`）现算，推送源从 `flow_slots`（`WHERE source=该源ID`）读取。升级前遗留的 `source=''` 历史连接只进汇总两页，在线状态页看不到、等新数据积累。
- 路由器数据**不混入**代理统计，`flow_slots` 与 `connections` 是两张独立的表，各自随保留天数清理。

## 活跃强度（1–6 档）

- 颜色表示「相对本源有多忙」，各源把原始活跃量按阈值映射到 1–6 档，便于跨源对比，而不是一个跨源可比的绝对数字。
- 档位之外，接口同时返回每槽原始活跃量（`RawValues`）：在线状态页悬停色块与峰值文案会显示绝对数值。两个源的口径现在一致，都是**真实并发连接数**（Clash 为代理并发连接，推送源为按五元组去重的并发连接），单位一致、可直接对比。颜色仍按档位取色，不受原始数值量级影响。
- **只统计并发连接数**：字节、包量加权代价大、收益不明显，且会破坏跨源归一化、重新引入下行 / NAT 归属问题，因此不采用；原 Clash 数据的字节字段是逐连接累计值、缺少按槽时间序列，要加权得新建聚合表，得不偿失。
- **阈值可按数据源自定义**：阈值是 5 个分界值（逗号分隔，如 `2,20,50,150,254`），超过最后一个即 6 档；只是视觉参数，不受传输字节限制（档位在查询时由槽值现算，槽值为 `uint16`、上限 65535，改造前 `[288]byte` / 封顶 255 的单字节约束已不存在）。
- 全局默认 `2 / 20 / 50 / 150 / 254`（与改造前前端一致，单 Clash 源逐槽颜色零回归）。在 `/data-sources` 页编辑数据源时开启「在线热度阈值」的「自定义」即可单独设置，关闭 / 留空则用默认；必须是 5 个严格递增的正整数，`PUT` 时校验。每台设备、每个用户的量级不同，阈值不写死在代码里。
- 推送源改为并发连接数后，量级与旧的「上行流数」口径不同，先观察实际分布再按需在管理页调整阈值，不要在代码里写死。
- 热度槽宽是 5 分钟；`active-flow-timeout` 是 RouterOS 长流导出超时，不是采集频率，且**不再影响计数**（见下）。

## 数据源定义与管理页

- 数据源定义存于 `data_sources` 表，在 `/data-sources` 页增删改；表格里三个开关各自独立切换（采集用开关、汇总用开关、在线默认用单选 radio），`PUT` / `DELETE` 后即时重建采集器。这是**运行时唯一**的数据源配置来源，也是**统一切换数据源的地方**（统计页不再各自切换）。
- 每行还带 `thresholds` / `custom_thresholds`（自定义「在线热度阈值」，见上「活跃强度」）；改动只影响该源的在线状态颜色，立即生效、无需重启。
- 所有数据源恒可被设为在线默认，不按「采集」开关过滤；关闭采集的源仍可看历史数据。
- 系统级配置（Web 端口、日志、保留天数）在 `config.toml` / 环境变量里，不进表；与数据源定义无关。
- **凭据两种来源（二选一，环境变量优先）**：
  - 「凭据引用」填环境变量名（如 `CLASH_SECRET`），运行时从该环境变量读真值（适合 Docker / 高级用法）；
  - 或「API 密钥」直接填写，密钥**轻量可逆混淆后存进 `data_sources` 表**（`credential_value` 列）。这是混淆不是加密，只防「随手翻库看到明文」；页面与接口都**不回显**明文或混淆串，只返回「来源 env/table + 是否已配置」。编辑时密钥框留空表示不修改。详见 [配置与部署](configuration.md)。
- **空表是合法状态，且是全新部署的初始状态**：v2.2.0 起**不做任何播种**，初始 0 数据源。在线状态页显示「暂无数据源」引导、不请求 `/api/gantt`；管理页空表提供「添加 Clash 源 / 添加 IPFIX 源」快捷按钮（只预填默认值，保存前可改）。删光所有数据源后重启保持空表，不会复活。

### Clash 源（代理轮询）

轮询外部控制器 `/connections`，行为与改造前一致；地址、轮询间隔、凭据可在管理页配置。凭据解析：数据源 `credential_ref` 非空 → 取它指向的环境变量；为空 → 解混淆表内 `credential_value`。运行时配置只认 `data_sources` 表，**不再回落到 `config.toml` 的 `[clash].secret`**（该段已删除）。每条连接按 `[start, last_seen]` 覆盖的每个 5 分钟槽各计一次并发连接。

### IPFIX 源（路由器流量推送）

- 接收路由器 UDP 推送的 NetFlow v9 / IPFIX 报文，只写 `flow_slots` 表。**不存原始流的逐包明细**：解码出五元组后，按 `(source, 五元组, 5 分钟槽)` 去重落库，一行代表一条连接在一个槽里出现过。
- **真实并发连接数**：查询时按 `(src_ip, 槽)` 统计行数，即该客户端该槽里不同五元组的数量。长连接被 RouterOS `active-flow-timeout` 切成多个分片、或分片重复上报，因为五元组相同且落在同一槽，主键唯一约束会合并成一行，计数不受切片时长影响。
- 五元组 = `源IP, 源端口, 目的IP, 目的端口, 协议`（IE8 / IE7 / IE12 / IE11 / IE4）。IPFIX 没有连接 ID 或 FIN/RST 标志，无法像 Clash 那样「一条连接一行带精确区间」，因此采用按 `(五元组, 5 分钟槽)` 去重：唯一可能的低估是同一 5 分钟槽内两条独立连接恰好五元组完全相同，实测极少见。
- 不做 TTL / 内存连接表：IPFIX 无法区分「同一长连接的切片」与「独立连接复用了相同五元组」，实测 150 秒内约 12.7% 的五元组重复出现且没有首尾相接，TTL 合并会把独立短流误并成一条长连接。按槽去重是无状态、可重启、与切片时长无关的方案。
- IPv4 模板字段（IANA IPFIX IE）：`4, 7, 8, 11, 12, 21, 22, 60`，共 8 字段 / 22 字节；一期忽略 IPv6 模板。
- **只算上行**：仅当源地址（IE8 `sourceIPv4Address`）落在 LAN 网段才归属给客户端。IPFIX 是单向流，配合上行过滤可避免同一连接上下行重复计数，因此不需要 NAT / MAC 字段来反查下行归属。
- `first/last-forwarded`（IE22 / IE21）是相对设备启动的毫秒值，用报文头的绝对 Export Time 反推 bootTime（取近期样本中位数抗抖动）再换算成绝对时间区间；一条流在其 `[start, end]` 覆盖的每个 5 分钟槽各写一次去重行。
- 排除 `exclude_ips`（通常填网关）与路由器（导出源）自身 IP。
- **无感认证**：RouterOS Traffic Flow 走 UDP 推送到采集机 IP:端口，零账号密码；官方 REST API 必须 Basic Auth，不用它。

#### 数据量

`flow_slots` 每行约 90 字节（含主键索引），按当前实测速率约 60 万连接记录/天、30 天约 0.18 亿行 ≈ 1.7–2.0 GB；按 10 倍极限估算约 17–20 GB。数据随 `db_cleanup_days`（默认 30 天）按 `slot_ts` 滚动清理，不会无限增长。

#### RouterOS Traffic Flow 配置要点

- Traffic Flow 目标指向运行本程序的主机 IP 与 UDP 端口（默认 `2055`，在 `/data-sources` 页配置）。
- 模板只保留上面 8 个 IPv4 字段，取消 NAT Src./Dst. Address 与 Src./Dst. MAC Address。
- 网络 / 防火墙需放行到采集机该 UDP 端口的报文；Docker 部署要发布 UDP 端口（见下）。

## 数据源配置（v2.2.0 收敛）

数据源运行时的真实配置**只认 `data_sources` 表**：`config.toml` 只留 `[server]` 系统项，环境变量只留系统项（`LOG_LEVEL` / `WEB_PORT` / `DB_CLEANUP_DAYS` / `DB_VACUUM_INTERVAL`）与可选的 `CLASH_SECRET`（凭据引用指向它时生效）。`CLASH_HOST` / `CLASH_INTERVAL` / `IPFIX_PORT` / `IPFIX_LAN` / `IPFIX_EXCLUDE_IPS` 等数据源相关 env 与 config 段**全部删除**，不做 env 一次性注入、不播种。全新部署初始 0 源，用户进 `/data-sources` 用快捷按钮添加。详见 [配置与部署](configuration.md)。

**数据源有效性（v3.1.0）**：管理页左侧「状态」列显示每个源的运行时健康。状态由**采集动作本身**推导，不做额外探测、不落库 —— Clash 每次成功 `GET /connections` 即连通证据，IPFIX 每收到一个 UDP 流即到达证据。判据：Clash 连续失败 ≥ 3 次 → 警告（抗单次抖动，成功清零）；IPFIX 距最近一次收到流 ≥ 5 分钟 → 警告（状态在读取时按时间推导，无需后台定时器）。四态：`等待`（黄，采集器已起还没首次结果）、`正常`（绿）、`警告`（红）、`已停用`（灰，采集关闭的源无证据）。重启后从 `等待` 开始是对的。前端每 60 秒轮询只读接口 `GET /api/data-sources/status`。

Docker 接收推送需发布 UDP 端口，例如 `-p 2055:2055/udp`，compose 里写 `"2055:2055/udp"`。若容器用 macvlan 拿到局域网同网段 IP，推送可直接到容器 IP，按需决定是否发布端口。

## 版本与迁移基线

- v2.0.0 是较大的一次改动：多数据源、`Collector` 采集层抽象、活跃强度归一化、数据源管理页。
- **v2.1.0**：推送源从「上行流数」改为按 `(source, 五元组, 5 分钟槽)` 去重的真实并发连接数（B 方案），新增 `flow_slots` 表；两源单位统一为「并发连接数」，计数不再受 `active-flow-timeout` 切片时长影响。
- **v2.2.0**：配置来源收敛 —— 数据源定义彻底只认 `data_sources` 表，删掉一次性播种，删掉 `[clash]` / `[ipfix]` 配置段与全部数据源相关环境变量；首次启动生成 `config.toml` 后不再退出；数据源表新增 `credential_value` 列支持直接保存轻量混淆后的 Clash 密钥。
- **v3.0.0**：按源隔离落盘 + 统一切换。三个独立开关（采集 / 汇总 / 在线默认）；`connections` 改 `(source, id)` 复合主键、写入打数据源 ID；在线状态取消页面下拉、严格按「在线默认」真实源 ID 隔离取数；目标 / 客户端统计按「汇总」开关过滤（含明细弹窗）；迁移基线改为 **v2.2.0**，v2.2.0 之前不再支持自动迁移。
- **v3.1.0（当前）**：数据源管理页新增「状态」列，显示每个源的运行时有效性。状态由**采集动作本身**推导，不做额外探测、不落库 —— Clash 每次成功 `GET /connections` 即连通证据（连续失败 ≥ 3 次转警告、成功清零），IPFIX 每收到一个 UDP 流即到达证据（距最近一次 ≥ 5 分钟转警告）。三态 + 灰：`等待`（黄，启动后还没首次结果）、`正常`（绿）、`警告`（红）、`已停用`（灰，采集关闭的源）。只读接口 `GET /api/data-sources/status` 返回 `{health:{<源id>:{state,last_ok_at,fail_count,message}}}`，前端每 60 秒轮询。
- **数据库迁移基线为 v2.2.0**：升级只做两件事，都在一个幂等流程里 —— 给 `data_sources` 补 `in_summary` 列（默认 1，ipfix 行强制 0），把无 `source` 列的旧 `connections` 事务性重建为 `(source, id)` 复合主键并整表复制存量数据（**按列名**复制 `INSERT INTO connections (source, 列…) SELECT '', 列… FROM 旧表`，而非 `SELECT *,`——历史库里 `last_seen_timestamp` 等列经 ALTER 追加在表尾、物理顺序与建表 DDL 不同，按位置复制会串列损坏数据；存量行 `source=''`、默认纳入汇总两页）。启动前用 `PRAGMA table_info(data_sources)` 校验 `credential_value` 列存在，低于 v2.2.0 的库（无 `data_sources` 表或缺 `credential_value`）**明确报错、不再静默迁移**，请先用 v2.2.0 过渡。
- **v2.2.0 之前的历史迁移 / 兼容代码已全部删除**（旧索引清理、`inbound_name` 名称清理、旧版补列、内置 `ipfix` 阈值迁移 `migrateSourceColumns` 等），以减少冗余。
- 升级代价：在线状态页严格只认该源 ID，存量 `source=''` 历史连接不进在线状态页，升级后在线状态历史热度会消失一段时间、等新数据按源积累（用户已接受）；目标 / 客户端统计不受影响，存量历史连接默认仍纳入汇总。
